Less Pull 1.4.4 — build 19

The version number stays 1.4.4 for good; the build number is what changes. Build 18 (never released) and build 19 add:

- Every display on its own. Each connected display gets its own color matrix and its own fade, driven by that display's refresh clock (a display link; 60 or 120 steps per second as the panel allows). The app in front decides its own display, website rule included; every other display follows the app whose window is on top there, with its exception or the defaults; an empty display shows the defaults. Any number of displays. Night Shift, Pause, Grayscale off for a while and the Toggle shortcut stay global. Peek on: all displays, or only the display with the active window (Settings → Shortcuts).
- A welcome tour on the first launch: four pages (the screen, exceptions, Peek, privacy) in the same card at the same size, Skip tour always visible, reopenable from About → Tour.
- Default shortcuts for new users: Option-A to peek and Option-Command-G to toggle Grayscale, each only if free on that Mac and keyboard; changeable under Shortcuts. Existing users keep what they have.
- About → Report a Problem… opens a new GitHub issue with build, macOS version, display count and the diagnostics text filled in. Nothing is sent until you submit it there.
- Documentation: screenshots, recordings and screen sharing keep their normal colors (the matrix is applied after the picture is made); a figure shows it.

Build 20 (same day) adds Settings → General → Displays: every connected display, by name, with Follows what is on it / Always your defaults / Always plain, in color, stored by display UUID; and the Shortcuts wording "Left-clicking the menu-bar icon".

Build 21 (same day): Peek works per display by default, on the display with the window you are using; a double press keeps that display plain, another display can be kept the same way later, and a press on a kept display lets only that one go. "All displays" remains a choice under Shortcuts. A two-display test covers it.

Build 22 (same day): the per-display Peek acts on the display under the mouse pointer, so no window has to be chosen first.

Build 23 (same day): the Displays section and the install help explain the hardware arrow pointer that stays in color on some displays, with a button to the Pointer size setting (one notch larger fixes it).

Build 24 (same day): "On every display" per app exception (menu and Settings → Apps): while that app is in front, its settings and Peek cover all displays, for apps whose picture shows on another display (3D players, presenters). Works whether or not the exception is used.

Build 25 (same day): an attempt to place the menu-bar icon by preference; build 31 removes it, since current macOS ignores the "Preferred Position" preference (tested with many values) and always puts a new item at the left end of the third-party items. ⌘-drag moves it, and macOS remembers the place.

Build 26 (same day): "Peek on every display" per app exception, separate from "On every display": while that app is in front, Peek covers all displays instead of the one under the pointer.

Build 27 (same day): "Peek toggles" per app exception replaces "Peek on every display": the display under the pointer, all displays, or any set of connected displays (stored by display UUID). A double press keeps that whole set; the next press lets it go.

Build 28 (same day) was meant to make an app's own Peek toggles choice win over the global Peek scope (All displays) on the Shortcuts tab, but shipped without that change; build 29 has it.

Build 30 (same day): Settings show what is relevant. Display options (the Displays section, Peek on, On every display, Peek toggles) appear only with two or more displays connected; the fine-tuning (what Peek turns off, mouse buttons, display options with one display) sits behind Show advanced options at the bottom of General. App and website rows are two lines with More for warmth and display choices; a row opens by itself the first time when something is set there. Website exceptions have the same display choices as apps (On every display, Peek toggles), kept by the bridge. Choices stay saved while hidden; a display keeps its choices when plugged in again (tested).

Build 31 (same day): Sessions. Start a session from the menu (lengths under Settings → Sessions); the icon shows a filling ring and the minutes left; at the end a warm glow on every display with one line of text and a soft gong (pure tones on 432 Hz and the solfeggio pitches 132/198/264/396 Hz), then the count goes on past the end (−0, −1, …) with optional reminders every 3/5/10/15 minutes or never; a click on the icon opens a panel under it (the other button opens the menu): End session while running; Keep going / Leaving now once over; Leaving now offers Call me back in (your presets) and Not today; the call back comes once, with two rising notes, and the session ends. Sound and glow can be turned off; Try it previews both. A twelfth suite tests the session model. Also: the one-display option counts only with Show advanced options on; the Displays rows keep a fixed width.

Build 32 (same day): reminders after the end are off by default; the count past the end breathes to invite a click; the panel offers the call-back choices directly with Keep going, Leave quietly and a gear to the Sessions tab; Night Shift toggled from Less Pull keeps the warmth you set by hand; the first launch opens the welcome right under the menu-bar icon and lets the icon fade in and out, since macOS does not let an app choose the icon's spot (preference under both names and many values, the private priority call, per-host storage: all tested, none honored).
